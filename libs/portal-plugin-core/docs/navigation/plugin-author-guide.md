# Navigation Plugin Author Guide

How to define routes with navigation in your plugin. For implementation details (how the pipeline works internally), see the [Navigation System](./README.md) doc.

## Basic Route with Navigation

Every route you want in the sidebar menu needs a `navigation` object with at least a `label`:

```tsx
import {
  createNamespacedId,
  type RouteDefinition,
} from "@lumeweb/portal-framework-core";
import { lazyIcon } from "@lumeweb/portal-framework-ui-core";

const Home = lazyIcon("Home");

const routes = [
  {
    path: "/dashboard",
    component: "dashboard",
    id: createNamespacedId("myplugin", "dashboard"),
    navigation: {
      label: "Dashboard",
      icon: Home,
      description: "Overview of your account and services",
      order: 0,
    },
  },
] satisfies RouteDefinition[];
```

## Navigation Properties

| Property | Type | Required | Description |
|----------|------|----------|-------------|
| `label` | `string` | Yes | Display label in the sidebar |
| `icon` | `React.FC` | No | Icon component shown before label |
| `description` | `string` | No | Tooltip text shown on hover |
| `order` | `number` | No | Sort order within section (lower first, undefined last) |
| `section` | `string` | No | Section header grouping (e.g., "Account", "Public Data") |
| `parentId` | `NamespacedId` | No | Explicitly nest under a parent in another plugin (e.g., `"core:account-layout"`) |
| `linkable` | `boolean` | No | If `false`, renders without a link (for parent groups). Default: `true` |
| `hidden` | `boolean` | No | Hide from navigation but keep route accessible |
| `disabled` | `boolean` | No | Show greyed out, non-clickable |
| `badge` | `{ content, variant? }` | No | Badge pill next to label |
| `show` | `() => boolean` | No | Dynamic visibility function |
| `forceShowInNavigation` | `boolean` | No | Force index routes to appear in nav (filter, not displayed on item) |
| `children` | `NavigationItem[]` | No | Inline child nav items |

> **Note**: `parentId` is auto-generated by the framework when you use the route `children` array. You can also set it explicitly on `navigation.parentId` to nest a route under a parent defined in another plugin — for example, billing routes use `parentId: "core:account-layout"` to nest under the dashboard's account layout.

## Sections

Set `section` on the navigation config to group items under a visual header. Children without their own `section` inherit the parent's. See [Navigation System: Section Grouping](./README.md#section-grouping) for how the framework processes this.

```tsx
// Standalone item in a section
navigation: {
  label: "Files",
  section: "Public Data",
  order: 10,
}

// Parent with section — children inherit automatically
{
  navigation: {
    label: "My Account",
    section: "Account",
    order: 3,
  },
  children: [
    { navigation: { label: "Profile" } },           // inherits "Account"
    { navigation: { label: "Security" } },           // inherits "Account"
    { navigation: { label: "API Keys" } },           // inherits "Account"
  ],
}
```

Current sections in use:

| Section | Items | Notes |
|---------|-------|-------|
| (default) | Dashboard, Operations | No header rendered |
| Public Data | Files (IPFS), Devices + Streams (LBRY) | |
| Private Data | Private Data (Sia) | Single item — header suppressed |
| Account | My Account, Subscription, Credits | |

## Nested Routes

Use the route `children` array to create hierarchy. The navigation system walks the tree and builds `parentId` relationships automatically. For cross-plugin nesting where a route lives in one plugin but should nest under a parent in another, set `parentId` explicitly on the navigation config.

```tsx
{
  path: "/account",
  component: "account/layout",
  id: createNamespacedId("myplugin", "account"),
  navigation: {
    label: "My Account",
    linkable: false,   // parent is not clickable, just a group
    section: "Account",
    order: 3,
  },
  children: [
    {
      path: "",
      component: "account/profile",
      index: true,
      navigation: {
        label: "Profile",
        forceShowInNavigation: true,
      },
    },
    {
      path: "security",
      component: "account/security",
      navigation: { label: "Security" },
    },
  ],
}
```

## Index Routes

Index routes (`index: true`) are excluded from navigation by default. To force one to appear, set `forceShowInNavigation: true`:

```tsx
{
  path: "",
  index: true,
  component: "overview",
  navigation: {
    label: "Overview",
    forceShowInNavigation: true,
  },
}
```

## Layout Routes (No Navigation)

A route without a `navigation` field won't appear in the sidebar, but its children are still processed. Use this for layout wrappers:

```tsx
{
  path: "/services",
  component: "services/layout",
  // No navigation: won't appear in sidebar
  children: [
    {
      path: "ipfs/files",
      component: "file-manager",
      navigation: {
        label: "Files",
        icon: Folder,
        description: "Browse and manage IPFS files",
        section: "Public Data",
        order: 10,
      },
    },
}
```

## Route Naming Conventions

- **Service routes**: `/services/<name>/...` (e.g., `/services/ipfs/files`)
- **Account routes**: `/account/...` (e.g., `/account/credits`)
- **IDs**: Always use `createNamespacedId(namespace, "name")` — bare strings are rejected
- **Plugin namespace**: Use your plugin's namespace consistently for IDs

## Complete Example

```tsx
import {
  CORE_NS,
  createNamespacedId,
  type RouteDefinition,
} from "@lumeweb/portal-framework-core";
import { lazyIcon } from "@lumeweb/portal-framework-ui-core";

const Folder = lazyIcon("Folder");
const UserCog = lazyIcon("UserCog");
const User = lazyIcon("User");
const Shield = lazyIcon("Shield");

const routes = [
  // Top-level item, default section (no header)
  {
    path: "/dashboard",
    component: "dashboard",
    id: createNamespacedId("myplugin", "dashboard"),
    navigation: {
      label: "Dashboard",
      icon: Folder,
      description: "Overview of your account and services",
      order: 0,
    },
  },

  // Sectioned service route
  {
    path: "/services/ipfs/files",
    component: "file-manager",
    id: createNamespacedId("myplugin", "files"),
    navigation: {
      label: "Files",
      icon: Folder,
      description: "Browse and manage IPFS files",
      section: "Public Data",
      order: 10,
    },
  },

  // Parent with children, section inherited
  {
    path: "/account",
    component: "account/layout",
    id: createNamespacedId("myplugin", "account"),
    navigation: {
      label: "My Account",
      icon: UserCog,
      description: "Manage your account settings",
      linkable: false,
      section: "Account",
      order: 3,
    },
    children: [
      {
        path: "",
        index: true,
        component: "account/profile",
        navigation: {
          label: "Profile",
          icon: User,
          forceShowInNavigation: true,
        },
      },
      {
        path: "security",
        component: "account/security",
        navigation: { label: "Security", icon: Shield },
      },
    ],
  },
] satisfies RouteDefinition[];

export default routes;
```
