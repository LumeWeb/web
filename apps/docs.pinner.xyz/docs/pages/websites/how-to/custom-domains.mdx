# Custom Domains

By default, your site is available at a `*.pinner.xyz` subdomain. To use your own domain, you need to prove ownership and configure DNS.

## Subdomain vs custom domain

| Type | Example | Setup |
|------|---------|-------|
| Subdomain | `mysite.pinner.xyz` | Automatic — no DNS needed |
| Custom domain | `mysite.example.com` | Requires DNS validation and records |

## Step 1: Create the website with your domain

:::code-group
```typescript [SDK]
const site = await pinner.websites.createWebsite({
  domain: "mysite.example.com",
  target_type: "ipfs",
  target_hash: "QmYourCID",
});
```

```bash [CLI]
pinner website deploy ./dist --domain mysite.example.com
```
:::

Pinner assigns a `validation_token` to the website. You'll need this in the next step.

## Step 2: Add the validation TXT record

At your domain registrar, create a TXT record:

| Record | Name | Value |
|--------|------|-------|
| TXT | `_pinner-validation.mysite.example.com` | `verify=<validation_token>` |

The `validation_record_host` field on the website tells you the exact hostname for the TXT record.

## Step 3: Trigger validation

:::code-group
```typescript [SDK]
const result = await pinner.websites.validateWebsite(site.id);
if (result.valid) {
  console.log("Domain validated!");
} else {
  console.log("Not yet valid:", result.reason, result.message);
}
```

```bash [CLI]
pinner website validate <site-id>
```
:::

DNS propagation can take a few minutes. If validation fails with `dns_missing`, wait a few minutes and retry.

## Step 4: Point DNS to Pinner

Add a CNAME record to route traffic:

| Record | Name | Value |
|--------|------|-------|
| CNAME | `www` | `sites.pinner.xyz` |

For root domains (`example.com`), use an A record — check `getWebsiteConfig()` for the IP.

```typescript
const config = await pinner.websites.getWebsiteConfig();
console.log("Gateway domain:", config.gateway_domain);
console.log("Nameservers:", config.nameservers);
```

## Step 5: Wait for SSL

SSL provisions automatically after DNS is in place. See [SSL](/websites/concepts/ssl) for details on checking status.

## Use Pinner-managed DNS

If you don't want to manage DNS at your registrar, enable Pinner's DNS hosting. This delegates DNS management to Pinner entirely.

### Enable during website creation

```typescript
const site = await pinner.websites.createWebsite({
  domain: "mysite.example.com",
  target_type: "ipfs",
  target_hash: "QmYourCID",
  dns_hosting_enabled: true,
});
```

### Enable on an existing website

```typescript
await pinner.websites.updateWebsite(site.id, {
  dns_hosting_enabled: true,
});
```

When DNS hosting is enabled, Pinner creates a DNS zone for your domain and handles the validation and CNAME records for you. Update your domain registrar's nameservers to point to Pinner's nameservers (shown in `getWebsiteConfig()`).

See [Manage DNS Zones](/dns/how-to/manage-zones) and [Manage DNS Records](/dns/how-to/manage-records) for the DNS-specific commands.

## Troubleshooting

### Validation keeps failing with `dns_missing`

DNS propagation can take up to 48 hours (usually a few minutes). Verify the TXT record exists:

```bash
dig TXT _pinner-validation.mysite.example.com
```

### Validation fails with `dns_mismatch`

The TXT record exists but the token doesn't match. Check that you copied the `validation_token` exactly — no extra whitespace or line breaks.

### Validation fails with `token_expired`

The validation token has expired. Re-create the website or update it to get a fresh token.
