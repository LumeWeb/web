# Migrate from Pinata

## Why migrate?

- **Privacy-focused infrastructure** — your data, your control
- **Competitive pricing** — pay for pinning, not bundled gateway infrastructure
- **Multi-network access** — one service, multiple storage networks
- **Drop-in compatibility** — swap the SDK, keep your API calls

## Migration strategy

| Approach | Best for | Effort |
|----------|----------|--------|
| **Pinata Adapter** | Quick migration, minimal code changes | Low |
| **Native Pinner API** | Long-term projects, better features | Medium |

:::tip
Start with the adapter to ship fast, then migrate to the native API when you want Pinner-specific features.
:::

## Adapter setup

### Install Pinner

```bash
pnpm add @lumeweb/pinner
# or
npm install @lumeweb/pinner
# or
yarn add @lumeweb/pinner
```

### Pick your adapter

**Pinata SDK 2.x** — use `pinataAdapter`:

```typescript
import { Pinner } from "@lumeweb/pinner";
import { pinataAdapter } from "@lumeweb/pinner";

const pinner = new Pinner({ jwt: process.env.PINNER_API_KEY });
const adapter = pinataAdapter(pinner);
```

**Pinata SDK 1.x** — use `pinataLegacyAdapter`:

```typescript
import { Pinner } from "@lumeweb/pinner";
import { pinataLegacyAdapter } from "@lumeweb/pinner";

const pinner = new Pinner({ jwt: process.env.PINNER_API_KEY });
const adapter = pinataLegacyAdapter(pinner);
```

## Step-by-step: replace initialization

1. **Replace the import.** Swap `pinata` for `@lumeweb/pinner` and import the adapter.
2. **Replace the constructor.** Instead of `new PinataSDK({ pinataJwt })`, use `new Pinner({ jwt })` + adapter.
3. **Add `.execute()` to builder methods.** The v2 adapter uses a builder pattern — chain methods, then call `.execute()`.
4. **Test uploads and listings.** Verify your existing calls work with the adapter.

## Migration checklist

- [ ] Install `@lumeweb/pinner`
- [ ] Update imports and initialization
- [ ] Replace API calls with adapter calls
- [ ] Add `.execute()` to builder methods (v2 adapter)
- [ ] Test file uploads
- [ ] Test file listing and deletion
- [ ] Update error handling (see [Error Reference](/errors))
- [ ] Remove Pinata SDK dependency
- [ ] Deploy and monitor

## Error handling

Pinner errors use a different structure. Instead of catching generic errors:

```typescript
import { PinnerError } from "@lumeweb/pinner";

try {
  const result = await adapter.upload.public.file(file).execute();
} catch (error) {
  if (error instanceof PinnerError) {
    console.error("Code:", error.code);
    console.error("Message:", error.message);
    console.error("Retryable:", error.retryable);
  }
}
```

See the [Error Reference](/errors) for all error codes and retry guidance.

## Testing your migration

1. **Test in development** — verify all upload operations work
2. **Check file listings** — ensure metadata is preserved
3. **Verify deletions** — test unpin operations
4. **Monitor performance** — compare upload speeds
5. **Review costs** — check your billing
